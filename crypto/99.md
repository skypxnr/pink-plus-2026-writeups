## TL;DR

1. The hint is hex with every byte bit-flipped (`XOR 0xFF`). It decodes to `https://github.com/QWERTZexe/QWERTZ-99`, the repo of the cipher used by the challenge.
2. `pink.qmap` is the cipher's substitution table (character to 3-digit number). `secure.png` is a 25×25 noise image that stores the ciphertext, and the repo's `img.py` decodes it.
3. The decoded number ends with `-98`, which means it is *salted with a password*. The salt is multiplicative, so the password can be recovered by checking which character codes divide the number.
4. The password is `13371337`. Dividing it out and mapping the 3-digit chunks back through the qmap gives the message and the flag.

## 1. The hint

```python
h = "978b8b8f8cc5d0d098968b978a9dd19c9092d0aea8baadaba59a879ad0aea8baadaba5d2c6c6"
print(bytes(b ^ 0xFF for b in bytes.fromhex(h)))
# b'https://github.com/QWERTZexe/QWERTZ-99'
```

The first bytes `97 8b 8b 8f 8c` flip to `68 74 74 70 73`, which is `https`, so the whole string is a bitwise NOT of an ASCII URL.

## 2. Understanding the `.qmap` file

```
[QMAP]{c:3}{s:1}(32|223)(33|182)(34|734)(35|973)...
```

- `{c:3}` means every character is encoded as a **3-digit** number.
- Each `(ord|code)` pair maps a character code to a unique code in `100..998`. For example `P` (80) → `727`, `I` → `565`, `N` → `179`, `K` → `407`, `{` → `962`.
- The map is a random permutation, so it is a plain substitution that only works with the right qmap file.

Encoding a message means concatenating the codes into one big decimal number. The repo then optionally **salts** it with a password (see below) and hides the number in an image.

## 3. Understanding `secure.png`

The image is 25×25 RGBA and looks like pure noise. Each pixel is really two bytes stored redundantly, with a few counts of noise on top. Even and odd pixels pair their channels differently (`R≈G, B≈A` versus `R≈A, G≈B`). The repo's `img.py` implements the decoder:

```python
import img
s = img.decode_image("secure.png")
# '5013871940811987917117653859100900183928...-98'
```

The result is a long decimal number with a `-98` suffix. In the QWERTZ-99 scheme, the suffix means "salted with a password" (`99` marks "no password").

## 4. The salt

Reading the repo's `main.py`, the password is turned into a number:

```
pw(p) = int( concat(code(c) for c in p) ) * product( code(c) for c in p )
salted = encoded_int * pw(p)
```

Without the password the decoded integer `N` is useless, but the **product part** makes it breakable:

- `N = message * concat * product`, so the product of the password's character codes **must divide `N`**.
- Only a handful of characters have a code that divides `N`. For ASCII these were `+ 1 2 3 7 U V m p u`.
- A depth-first search over passwords built from those characters, where the running product must keep dividing `N`, prunes the search space to almost nothing.

Then for each candidate, check that `N % pw == 0` and that the quotient splits into valid 3-digit chunks.

(Shorter passwords like `1337` also divide `N`, which is a nice false lead: `13371337` contains `1337` twice, so `1337`'s factor divides as well.)

### Solver

```python
import re, sys
sys.set_int_max_str_digits(0)
sys.path.insert(0, "QWERTZ-99")          # git clone https://github.com/QWERTZexe/QWERTZ-99
import img

M = {chr(int(o)): m for o, m in re.findall(r"\((\d+)\|(\d+)\)", open("pink.qmap").read())}
inv = {v: k for k, v in M.items()}

s = img.decode_image("secure.png")
assert s.endswith("-98")                 # salted
N = int(s[:-3])

def pw(p):
    pre = int("".join(M[c] for c in p))
    for c in p:
        pre *= int(M[c])
    return pre

# only characters whose code divides N can be in the password
cs = [c for c in M if N % int(M[c]) == 0 and ord(c) < 127]

def decode(q):
    q = str(q)
    if len(q) % 3:                       # trailing "99" end marker
        q = q[:-2]
    return "".join(inv.get(q[i:i+3], "?") for i in range(0, len(q), 3))

def dfs(p, prod):
    if p:
        P = pw(p)
        if N % P == 0:
            out = decode(N // P)
            if "PINK{" in out:
                print("password:", p)
                print(out)
    if len(p) >= 14:
        return
    for c in cs:
        v = prod * int(M[c])
        if N % v == 0:
            dfs(p + c, v)

dfs("", 1)
```

Result: the password is **`13371337`**.

## 5. Decoding the message

With the password divided out, the 3-digit chunks decode through the qmap to a friendly message ending in the flag:

> *Hey, thanks for trusting QWERTZ 99 with your most sensitive data! Here is your sensitive data in case you forgot it: `PINK{NiNeTyNiNeQwErTzEs}`*

The flag digits themselves are `727 565 179 407 962 ...` which read `P I N K {` through the qmap.

## Flag

```
PINK{NiNeTyNiNeQwErTzEs}
```

("NiNeTy NiNe QwErTz Es" = *99 QWERTZ ES*.)

## Takeaways

- A multiplicative password "salt" leaks information: the factors of the password's codes must divide the ciphertext, so you can search characters by divisibility instead of brute-forcing.
- Always check the hint for trivial encodings (here, a bitwise NOT) and look for the author's public repo when a challenge uses a custom format.
